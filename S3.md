# S3 Object Storage (optional)

fly.board stores uploaded files on the local disk under `public/uploads/` by default.
If you fill in `s3.settings`, uploads can **also** (or **instead**) go to any
S3-compatible object storage — AWS S3, MinIO, Cloudflare R2, Backblaze B2, etc.

`s3.settings` is **optional**. If the file is missing, an empty template is
created on first run and the server keeps using plain local storage.
If **every value is empty** (or any of `endpoint`, `bucket`, `access_key`,
`secret_key` is empty), S3 is considered disabled and nothing changes.

## How it works

Both upload paths (simple multipart upload and TASFA chunked upload) finish by
writing the file to `public/uploads/` and generating thumbnails/previews
locally — this never changes. After that, when S3 is enabled:

1. The finished file is PUT to the bucket as object `<prefix><basename>`
   using Signature Version 4 authentication.
2. What happens next depends on `mode`:
   - `mirror` (default): the local copy is kept. S3 is a live backup/external
     copy. Downloads keep being served from the local disk exactly as before.
   - `offload`: the local copy is deleted and the database row is marked
     `s3://<key>`. Downloads are answered with a 302 redirect to a
     time-limited (1 hour) presigned GET URL.
3. If the PUT fails, the upload stays on local disk and an error is logged —
   a misconfigured or unreachable bucket never breaks uploads.

Thumbnails and previews (`.thumbs/`, `.previews/`) always stay local; only the
original file is mirrored/offloaded.

Deletions (`/file/delete`, post deletion, duplicate cleanup, `drop_all`) remove
both the local file and the S3 object, whichever exist. S3 DELETE is
idempotent, so cleaning up after a mode switch is safe.

## Settings reference (`s3.settings`)

Plain `key=value` lines, same format as `blog.settings`. Empty means unset.

| Key | Required | Description |
|-----|----------|-------------|
| `endpoint` | yes | Base URL of the S3 endpoint, e.g. `https://s3.us-east-1.amazonaws.com` or `https://minio.example.com:9000` |
| `region` | recommended | Signing region, e.g. `us-east-1`. Defaults to `us-east-1` when empty (MinIO accepts anything) |
| `bucket` | yes | Target bucket name. The bucket must already exist |
| `access_key` | yes | Access key id |
| `secret_key` | yes | Secret access key |
| `prefix` | no | Key prefix prepended to every object, e.g. `uploads/` |
| `use_path_style` | no | `true` = `https://endpoint/bucket/key` (needed by MinIO and most self-hosted gateways). Empty/`false` = virtual-host style `https://bucket.endpoint/key` (AWS default) |
| `mode` | no | `mirror` (default) keeps the local file and also stores it in S3; `offload` moves it to S3 and deletes the local copy |

The file may contain `#` comment lines. `s3.settings` is listed in `.gitignore`
because it holds credentials.

## Example configurations

### MinIO (self-hosted, mirror mode)

```ini
endpoint=https://minio.example.com:9000
region=us-east-1
bucket=flyboard-uploads
access_key=flyboard
secret_key=change-me-long-random
prefix=uploads/
use_path_style=true
mode=mirror
```

### AWS S3 (offload mode)

```ini
endpoint=https://s3.ap-northeast-2.amazonaws.com
region=ap-northeast-2
bucket=my-blog-uploads
access_key=AKIA...
secret_key=...
prefix=flyboard/
use_path_style=false
mode=offload
```

### Cloudflare R2 (offload mode)

```ini
endpoint=https://<account-id>.r2.cloudflarestorage.com
region=auto
bucket=my-blog-uploads
access_key=...
secret_key=...
prefix=uploads/
use_path_style=true
mode=offload
```

## Operational notes

- **IAM permissions**: the credentials need `s3:PutObject` and
  `s3:DeleteObject` on the bucket, plus `s3:GetObject` if you use `offload`
  (presigned URLs are signed with these credentials).
- **TLS**: use `https://` endpoints. Payload signing uses `UNSIGNED-PAYLOAD`,
  which is only safe over TLS.
- **Latency**: the S3 PUT happens synchronously in the upload request, so a
  slow bucket makes uploads slower (mirror and offload alike).
- **Presigned downloads** (`offload`): clients are redirected straight to the
  bucket, so the bucket endpoint must be reachable from browsers. Presigned
  URLs expire after 1 hour.
- **Mode switching**: switching `mirror` ↔ `offload` does not migrate existing
  files. Rows offloaded earlier (`s3://` marker) keep downloading via presigned
  redirects; local rows keep serving from disk. Deletes clean up both sides.
